# Accessibility Guidelines

Comprehensive WCAG 2.1 AA accessibility standards for DocenteDoc AI.

## Overview

DocenteDoc is committed to making education accessible to everyone. All components and features follow Web Content Accessibility Guidelines (WCAG) 2.1 Level AA standards.

## WCAG 2.1 Principles

### 1. Perceivable

Information and user interface components must be presentable to users in ways they can perceive.

#### Alternative Text

All non-text content has text alternatives:

```tsx
// Images
<img src="classroom.jpg" alt="Students working on assignments in classroom" />

// Icons (decorative)
<span className="icon" aria-hidden="true">home</span>

// Icons (functional)
<button aria-label="Delete document">
  <span className="icon" aria-hidden="true">delete</span>
</button>

// Complex images
<figure>
  <img src="chart.png" alt="Grade distribution chart" />
  <figcaption>
    Chart showing student grades: 5 students with A, 10 with B, 8 with C, 2 with D
  </figcaption>
</figure>
```

Provide captions and transcripts:

```html
<video controls>

  <track kind="descriptions" src="descriptions-en.vtt" srclang="en" label="English descriptions" />

```

### 3. Understandable

Information and the operation of user interface must be understandable.

#### Clear Labels

All form inputs have associated labels:

```tsx
// Visible label
<div>
  <label htmlFor="student-name">Student Name</label>
  <input id="student-name" type="text" />
</div>

// ARIA label
<input type="search" aria-label="Search documents" placeholder="Search..." />

// Accessible description
<input
  type="email"
  aria-label="Email address"
  aria-describedby="email-help"
/>
<div id="email-help">We'll never share your email</div>
```

### 4. Robust

Content must be robust enough to be interpreted by assistive technologies.

#### Semantic HTML

Use proper HTML elements:

```html
<!-- Good: Semantic HTML -->
<header>
  <nav>
    <ul>
      <li><a href="/">Home</a></li>
      <li><a href="/about">About</a></li>
    </ul>
  </nav>
</header>

<main>
  <article>
    <h1>Document Title</h1>
    <section>
      <h2>Section Title</h2>
      <p>Content...</p>
    </section>
  </article>
</main>

<footer>
  <p>&copy; 2026 DocenteDoc</p>
</footer>

<!-- Bad: Div soup -->
<div class="header">
  <div class="nav">
    <div class="link"><a href="/">Home</a></div>
  </div>
</div>
```

#### ARIA Attributes

Use ARIA appropriately:

```tsx
// Buttons
<button aria-label="Close dialog">×</button>

// Toggles
<button aria-pressed={isActive}>
  {isActive ? 'Active' : 'Inactive'}
</button>

// Live regions
<div aria-live="polite" aria-atomic="true">
  {statusMessage}
</div>

// Dialogs
<div role="dialog" aria-labelledby="dialog-title" aria-describedby="dialog-description">
  <h2 id="dialog-title">Confirm Delete</h2>
  <p id="dialog-description">Are you sure you want to delete this document?</p>
</div>

// Tabs
<div role="tablist">
  <button role="tab" aria-selected={selected} aria-controls="panel-1">
    Tab 1
  </button>
</div>
<div role="tabpanel" id="panel-1">
  Content
</div>
```

## Testing Checklist

### Manual Testing

- [ ] Navigate entire app using only keyboard
- [ ] Check all focus indicators are visible
- [ ] Verify all images have alt text
- [ ] Ensure all forms have labels
- [ ] Test with screen reader (NVDA, JAWS, VoiceOver)
- [ ] Verify color contrast with tools
- [ ] Check touch target sizes on mobile
- [ ] Test with 200% zoom
- [ ] Verify video/audio has captions

### Automated Testing

```bash
# Install axe-core for automated testing
npm install --save-dev @axe-core/react

# Run accessibility tests
npm run test:a11y
```

```tsx
// Jest + Testing Library
import { axe, toHaveNoViolations } from 'jest-axe';

expect.extend(toHaveNoViolations);

it('should not have accessibility violations', async () => {
  const { container } = render(<MyComponent />);
  const results = await axe(container);
  expect(results).toHaveNoViolations();
});
```

## Screen Reader Support

### Announcements

Use live regions for dynamic content:

```tsx
// Polite announcements (wait for user to finish)
<div aria-live="polite" aria-atomic="true">
  Document saved successfully
</div>

// Assertive announcements (interrupt immediately)
<div aria-live="assertive" aria-atomic="true">
  Error: Failed to save document
</div>

// Status updates
<div role="status" aria-live="polite">
  Loading... {progress}%
</div>
```

### Hidden Content

Hide decorative content from screen readers:

```tsx
// Decorative icons
<span className="icon" aria-hidden="true">★</span>

// Visually hidden but accessible
<span className="sr-only">
  Current page: Home
</span>

<style>
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
</style>
```
