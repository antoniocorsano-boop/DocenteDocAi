Developer Guidelines

Using Semantic Tokens

  • Always prefer semantic tokens: Use --app-* tokens instead of direct --md-sys-* tokens
  • Consistent naming: --app-color-primary, --app-spacing-container, --app-elevation-level-1
  • ESLint enforcement: Rules automatically flag non-compliant usage
  • Pre-commit hooks: Prevent MD3 violations before commits
  • Documentation: Check semantic-tokens.css for available tokens

Adding New Tokens

  • Follow --app-{category}-{variant} naming pattern
  • Reference existing MD3 tokens in semantic-tokens.css
  • Update ESLint rules if needed for new categories
  • Test across light/dark themes
  • Document usage in component comments

Maintenance

  • Quarterly MD3 specification audits
  • ESLint violations must be zero (except approved exceptions)
  • Build and test validation required for token changes
  • Backup files archived in /archive/md3-backups/
